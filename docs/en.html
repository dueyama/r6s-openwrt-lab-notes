OpenWrt router experiments with NanoPi R6S

A record of construction, monitoring and NPU experiments

As AI evolves and attack methods become more diverse, network defenses need to adapt too. In this experiment, we also use AI to understand activity on our home network and build tools that help us decide how to respond. The foundation is NanoPi R6S (R6S), a compact FriendlyElec computer, running the OpenWrt router operating system. The experiments have grown from traffic visibility to AI-assisted alert review and local NPU computation.

What the R6S offers for this experiment

We discussed the equipment with ChatGPT and selected the R6S, purchasing it from IoT Honpo in Japan. We already understood when choosing the board that its NPU would require additional integration to work with the standard official OpenWrt system. Its compact board brings together useful capabilities for routing, observation and computation experiments.

Three Ethernet ports

Two 2.5Gbps ports and one 1Gbps port.

Separate WAN (Internet side), LAN (home-network side) and another wired network. This provides a base for routing traffic and observing it.

Official OpenWrt support

Official device definitions and firmware images are available.

An official OpenWrt base supports custom functions alongside upstream features and updates. This experiment moved from manufacturer-provided FriendlyWrt before adding monitoring and the management interface.

Built-in eMMC for a permanent setup

This unit has 64GB eMMC.

Keeping the OS and logs on built-in storage is another advantage when prioritizing reliability. It avoids reliance on removable SD-card contacts and additional external-storage cables or enclosures in a permanent installation.

An NPU for local computation experiments

The RK3588S NPU is rated at 6TOPS by the manufacturer.

This dedicated machine-learning processor enables experiments with local numerical traffic-anomaly scoring. Its rating is not a measured speed for this experiment.

SD cards are useful for trials and recovery, but write endurance was also a concern for continuous operation with ongoing OS, log and database writes. Depending on capacity and write workload, an external USB SSD is another option for separate data storage. Endurance depends on the product and write conditions. This experiment uses eMMC for compact permanent operation and retains a verified SD card for alternate boot and recovery.

An eight-core CPU and this unit’s 8GB memory provide a platform for logging and aggregation alongside routing. Both microSD and eMMC boot are supported; initial trials kept the existing eMMC system while testing official OpenWrt from SD. The working SD was saved for recovery: eMMC is used normally, with the saved SD inserted for priority boot when needed. Detailed specifications follow below.

Official OpenWrt device support and NPU enablement are separate. This project separately integrated the NPU driver, Device Tree and runtime libraries for Linux 6.12. Local NPU scoring is also separate from GPT-6 Luna reviewing logs through the Responses API and an external service.

Key terms before reading
The 2022 / 2024 Macs
2022 means Mac Studio (2022, M1 Max); 2024 means Mac mini (2024, M4). These labels distinguish coordination/acceptance/records from authoritative development/builds.
Hardware names / Codex
R6S is the compact board used as the router. A Raspberry Pi is a compact single-board computer. Pi 3 abbreviates Raspberry Pi 3 Model B (board revision 1.2), the preliminary test platform; Pi 5 abbreviates Raspberry Pi 5, which handles authoritative logs/SQL, review control, notifications and primary backups. Codex is the AI development assistant used for implementation, builds and verification.
SoC / TOPS / number formats
An SoC integrates processors such as the CPU and NPU. TOPS is a rated operation-count metric. INT and FP denote integer and floating-point formats.
OpenWrt / FriendlyWrt
OpenWrt is a router OS. FriendlyWrt is FriendlyElec’s modified derivative, released and distributed separately from official OpenWrt. This project switched to official OpenWrt.
Snort / IDS
IDS means intrusion detection system. Snort records alerts for traffic matching detection rules.
AI-assisted traffic-log review
A custom workflow asking GPT-6 Luna (model ID: gpt-6-luna) through an external AI service to judge alerts and context; internally called Luna review.
NPU / anomaly score
An NPU accelerates machine-learning calculations. An anomaly score measures departure from learned patterns, not confirmed attacks.
Receipt (verification record)
A record binding the target version, evidence and result; its existence alone does not establish adoption or completion of every stage.
Formal finish (workflow acceptance)
Workflow completion after required originals, API and display evidence; distinct from fixing every software issue.
Projection / rebinding
Projection turns stored logs into aggregate/display data. Rebinding ties a review result to evidence for the corresponding configuration/version.

Two Codex apps and task coordination across projects

Both Macs run the Codex desktop app, each with different projects and assigned tasks. Work in this experiment is distributed between coordination and development/build tasks, which communicate across projects.

A typical sequence is:

  1. The coordination Mac task organizes the request, scope and acceptance conditions.
  2. Task-to-task messages carry requests and specifications to the build Mac owner, which proceeds with implementation and verification.
  3. The build Mac task returns questions, progress, source commits, artifact identities, verification results and remaining issues. Clarifications travel in both directions.
  4. The coordination Mac task checks artifacts against installation results and updates acceptance and records, returning required revisions to the owner.

Task messages coordinate the work, while source, build environments and artifacts stay under their machine owners. Commit and artifact identities in messages are linked to Git history, file hashes and installation records so deployed changes remain traceable.
