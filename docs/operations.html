用語の補足
上流 / stable branch
上流は元のOpenWrt等の開発元。stable branchは採用している安定版の更新系列。
ABI / backport
ABIは実行ファイルやモジュール間の互換性に関わる取り決め。backportは新しい系列の修正を古い系列へ移植すること。
APK / 永続化
APKはここではOpenWrtのソフト配布形式。永続化は再起動・更新後も設定や履歴を保持すること。
SQM / CAKE
通信待ち行列を制御し、回線が混雑したときの遅延を抑える仕組み。
PWA / Web Push
PWAはブラウザ画面をアプリのように使う仕組み。通知配信は2026-11-13にOneSignalから標準Web Pushへ移行した。
DNS / SSD
DNSは名前から通信先のアドレスを調べる仕組み。SSDはバックアップを置く記憶装置。
receipt（確認記録）
対象の版・根拠・結果を結び付けて残す記録。存在だけで実機導入や全工程の完了を示すものではない。
正式finish（工程の受入完了）
必要な原本・API・画面証跡などをそろえた工程上の完了。ソフトの全問題を直したという意味ではない。
投影 / 再結合
投影は保存ログを集計・表示用データへ整形すること。再結合は監査結果を対応する構成・版の根拠へ結び直すこと。

CVE-2026-98432：読み終える前にメモリを解放する競合

IPv4のTCP接続準備では、要求ソケットのIPオプションを子ソケットへ引き継ぎます。別CPUがSYNへの応答を作る間に子ソケットが破棄されると、参照中のオプションまで解放され得ました。解放後のメモリを使うuse-after-freeです。読み手はRCUという保護方式を使っていても、解放側が通常のkfree()では待ってくれないことが原因です。

領域サイズ・ダウンロード量・書込み量は別

10月23日には、拡張後の更新方式もオフラインで比較しました。既存の未導入OSイメージの内容を共通にし、p2の割当容量とゼロ埋め量を変えたMac上の合成比較です。空き部分は圧縮しやすいため、領域を大きくしてもgzipの容量は同じ割合では増えません。

gzipの値は配布用の末尾メタデータを含みません。右列はp1の16MiBも含む書込み対象量で、実機の書込み時間ではありません。圧縮入力を少しずつ展開して書き込む方式なら、5GiB全体を一度にRAMへ展開する必要もありません。ただし、通常の全域書込みではゼロ埋め部分も書きます。「ダウンロードは小さい」ことだけで、更新が速い・書込みが少ないとは判断できません。

確認したのは容量と書込み方式の仕組みです。実機での更新受入、F2FSの初期化、設定保持、再起動、通信停止時間はこの比較に含みません。容量を減らすかどうかはRAMだけで決めず、将来の追加機能と、検証済みの更新・復旧方式を合わせて考えます。

復元後の追補：ログ内容と処理位置の対応も必要

10月23日の復元後、Snortのログ内容は同じでも、ファイルシステム上の識別番号（inode）が変わり、差分収集が停止しました。収集処理は前回処理したファイルと位置を記憶しているため、内容が正しく戻っただけでは継続できない場合があります。

担当は保存元とログ全体の一致、すでに処理した範囲の一意な対応を確かめ、処理位置と過去履歴を保ったまま識別を一回移行しました。その後の通常収集、DBと処理位置の一致、管理画面での復帰を確認済みです。識別を無条件に無視したり、先頭・末尾からやり直す一般手順ではありません。復旧時は、内容・属性に加え、収集処理が記憶した状態との整合も確認します。
