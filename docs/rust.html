Python → Rust

どの処理を変え、時間と依存ソフトの保守範囲がどう変わったか。

本文更新：2026-11-11 · SQL改善と言語移行の比較条件

このページで紹介すること

処理が遅いとき、どこから直すと効果があるのか。この実験では、まずデータベースへの問い合わせを改善し、その後PythonとRustを比較しました。速さの変化に加え、ルーターに残す依存ソフトを減らした経緯を紹介します。

SQLの改善、言語の変更、依存ソフトの削減を別々に評価すると、どの変更が役立ったかを説明しやすくなります。

改善の順序と比較結果

用語の補足
Snort / SQLite
Snortはルールに基づく侵入検知ソフト。SQLiteはイベントと判断履歴を保存するデータベース。
Python / Rust / native
Pythonは初期実装に使った言語。Rust版はR6SのCPU向けにコンパイルした実行ファイルとして動かす。
SQL / transaction
SQLはデータベースの検索・更新命令。transactionは関連する更新をまとめて扱う単位。
cursor / schema / hash
cursorはログをどこまで処理したかの位置、schemaはデータ構造、hashは内容の同一性を照合する値。
CPU時間 / 最大RSS
CPU時間は計算に使った時間、RSSは実メモリ使用量。表の最大RSSは試験中の最大値。
crate / 依存除去
crateはRustのライブラリ等の単位。Python依存を除去したのはR6S上のこの処理で、外部PCの学習環境は別。

対象の版・根拠・結果を結び付けて残す記録。存在だけで実機導入や全工程の完了を示すものではない。

Python導入からRust移行・依存除去まで

初期のIDS監視機能は、CodexがPythonを導入して実装しました。その後、R6S上の処理をネイティブへ移し、Python依存を除去する方針でRustへ変更しました。対象はIDSログの解析・重複排除・集計・SQLite保存、監査用固定入力記録、判断履歴と表示データ生成の機械処理です。115特徴の計算・NPUモデル推論とは別の処理系として記載します。ログの意味を判断するAIとは別の、データ処理部分の変更です。

引用するときも、二つの比較を分ける

Python内のSQL改善は46.528秒→0.596秒。別の同じ10,000行を使う言語比較はPython 0.358秒／Rust 0.216秒です。「PythonからRustで46.5秒→0.2秒」と一つの比較にまとめることはできません。試験条件と比較対象は下の各表に記しています。

2026-09-27
Python版のSQLアクセスを改善。イベントごとに履歴を繰り返し検索していた処理を、トランザクション内で案件ごとの履歴改訂数を一度取得する方式へ変更。DB 12テーブルの結果一致と既存14状態試験を確認。言語の変更前にアルゴリズムとI/Oを見直した。
2026-09-28
同一Snortログ10,000行について、解析・重複排除・集計・SQLite保存をPython/Rustで各3回比較。各回は新規DB、実行順は交互。イベント・集約グループの両テーブルの全行が3回とも一致。
2026-10-06
R6SのCPU向けに必要なライブラリをまとめたRust実行ファイルへ本番の機械処理を移行。DB構造、バイト単位の処理位置、既存の判断履歴、固定入力記録のSHA互換を保持し、shell / ucode / ネイティブへ導入検査も移した。ネイティブ運用と依存関係を確認した後、R6SのPython関連パッケージを除去。削除後の収集とDB整合検査が成功した。

別条件の実運用例

Rust版への切替後は、8,762件の収集が5.52秒で完了した実運用記録もあります。これらの値は、前述の同一1万行によるPython/Rust比較とは入力・範囲が異なります。

セキュリティ保守対象の縮小

移行の成果は処理時間・メモリ使用量の変化だけではありません。2026-10-06の記録では、ネイティブ版の動作と逆依存を確認した後にPython関連21パッケージを除去し、R6S上のPythonパッケージが0件になったことを確認しています。これにより、そのR6Sに導入していたPython本体・標準ライブラリ・関連パッケージを、脆弱性の該当性確認と更新対応の対象から外せました。

これは依存コンポーネントと保守対象の削減です。Pythonを採用したこと自体を脆弱性と評価した結果ではなく、Rust製実行ファイル、依存crate、SQLite、OS等の確認・更新は引き続き必要です。Python除去だけでシステム全体の安全性が確定したとは扱いません。

切替時の互換性・実行環境の検証

最終版で19単体試験、25 CLI試験、8導入試験、16旧解析処理とのバイト単位の比較が成功。実機にない外部コマンドへの依存は、ucodeのstat処理とRustの期限・出力上限付き子プロセス処理へ置換した。切替時はDB/処理位置の再初期化を避け、読取り専用検査と既存履歴の継承を確認した。

Python依存除去は2026-10-06のR6S側処理についての記録です。外部PCの学習・管理ツールを含む全環境のPython廃止、完全復元、長期性能、通信停止時間を保証するものではありません。

SQLの往復を減らすと、何が変わるのか

同じ案件の改訂履歴をイベントごとに繰り返し検索していたため、トランザクション単位で案件別の数を一度読み、未登録の指紋が増えたときだけ数を更新する構造へ変えました。現在の指紋を除く規則は維持しました。保存記録では12テーブルの結果一致と、挿入・再試行を含む14件の既存試験を確認しています。
