今回の答え：保存範囲ではβ≈1を基準にできる

βは、許容する誤検出率を満たすか確かめながら、判定閾値を調整する感度係数です。今回のC72保存履歴では、全対象を正常と仮定した個別採点の誤検出率相当は、0.5で約0.0000198〜0.0111%の範囲に収まりました。論文の評価水準0.1%を比較の目安にするなら、保存範囲では上限も下回ります。βをさらに大きくしなければこの目安を満たせない、という根拠は見えていません。

ただし、これは確定した誤検出率や将来の保証ではありません。0.1%は論文との比較に使った目安で、本人が新たな固定目標として選んだ値ではありません。0.01%以下を求める場合は、今回の集計だけでは確認できません。本人が選んだ運用値0.5と、厳密なβ=1の値との小さな丸め差も、以下で区別します。

βは何を調整するのか

T = φ × β

Tは判定に使う閾値、φは学習中に記録した出力層RMSEの最大値、βはその基準を動かす倍率です。RMSEはモデルが入力を再構成したときの誤差で、ここでは異常度のスコアです。スコアは侵入確率ではありません。

同じ固定スコアならβを大きくするとTも高くなり、超過は増えません。ただし、異常も拾いにくくなる可能性があります。したがって「βを計算したから目標FPRに合格」ではなく、対象と分母を決め、正常と分かるデータで超過を数え、許容する誤検出と見逃しの兼ね合いを確認します。

論文§III-Eはβ≥1とし、更新前に計算した誤差から学習最大を記録します。§IV-Aも出力層の学習最大を保持します。§IV-Dは最大値方式を単純な案と位置付け、分布を使う別案も示しています。β=1が、どのネットワークでも最適になるという意味ではありません。

一次資料：Kitsune論文 §III-E・IV-A・IV-D

同じ論文に出る圧縮比のβ（この実験の設定では0.75）は、ここで説明する感度係数とは別の用途の記号です。また§III-Eの擬似手順はs≥T、今回の保存再集計はs>Tを使っています。境界値の扱いを同じものとして数え直してはいません。

0.22は、学習最大から決めた値ではなかった

これは観察を始めるための比較値でした。後から家庭の通常利用という仮定で頻度を評価したことと、最初に値を選んだ由来は別です。学習中の最大φ、学習を終えたモデルで選んだ入力を再採点した最大、実運用の一分最大は、それぞれ異なる統計量です。

追加の実機取得をせず、2026年10月25〜31日のC72単独運転で保存した44応答を使いました。モデル・履歴行の世代・処理時刻の一分を組にして重複を除き、重複51,994行を取り除いた後、訂正済みの観察集計と一致する9,202確定一分区間・5,053,722有効採点を確認しました。この時刻は処理時刻で、元パケットの到着時刻ではありません。D168の運用成績や並列モデルの履歴とは混ぜていません。

0.5を超えた確定一分区間は一つで、その最大値は約1.907914、区間内の有効採点は560件でした。「一分区間が一つ」は、一分間ずっと高かったこと、通知が一通だったこと、超過スコアが一件だけだったことの証拠ではありません。

別の部分区間にも最大約0.620361・485有効採点という超過がありましたが、確定区間の率の分母へは混ぜていません。部分・空・無効区間や最新の未確定範囲を除いており、未観測を0へ置き換えてはいません。過去の品質保留・再接続境界や未測定の欠測も、なかったことにはしていません。

一分最大と件数から、個別の誤検出率をどこまで言えるか

FPR = FP / (FP + TN)

FPは正常なのに超過した採点、TNは正常で超過しなかった採点です。「検出したものはすべて誤検出だった」と仮定しても、それだけでは分母FP+TNは確定しません。超過しなかった対象が正常か、見逃した異常かが分からないためです。以下では追加で「評価対象の全有効採点が正常だった」と仮定します。正常という正解ラベルを独立に確認した結果ではありません。

1 / 5,053,722 ≤ FPR* ≤ 560 / 5,053,722

百分率へ直すと、約0.0000197874%〜0.01108094%です。最大値が0.5を超えたため少なくとも1件、区間内560件がすべて超過した可能性までを上限にしています。これは保存された最大・件数から分かる識別範囲であり、点推定でも統計的信頼区間でも確定FPRでもありません。

0.1%なら収まるが、0.01%は確認できない

論文§V-C/DはFPR=0および0.001で性能を評価しています。0.001は割合であり、百分率では0.1%です。今回の全正常仮定の上限0.01108094%は0.1%より小さいため、その比較目安であれば、今回のC保存範囲でβ≈1を基準にする判断を支えます。これは実装したβが自動的にFPRを保証する、という意味ではありません。CとDのφが同じでも、このC72単独履歴の率をD168の運用FPRへ移すことはできません。Dの0.5は本人の選択であり、D自身の実績は別に観察するものです。

一次資料：論文のFPR定義と評価水準 §V-C/D

一方で上限は0.01%より大きいので、「0.01%以下を確認できた」とは言えません。実際の個別超過件数を知らないことが制約です。さらに、今回の単位は非空100ms区間の代表NPU採点で、論文の全パケット単位とは異なります。論文より高精度、将来も同じ率、攻撃を十分検出できる、という比較には使えません。

運用で見直す場合は、許容FPRと評価単位を先に決め、正常と確認できる別期間で検証し、見逃しも別に測る必要があります。同じ過去データを見ながら閾値を選び直した結果を、独立した将来検証の代わりにはしません。これは追加実験を自動的に始める予定ではなく、今回の判断の限界です。

2026-11-01：0.5を運用へ適用し、通常周期と読取りで確認

学習最大の再現とC72保存履歴の再評価に続き、本人承認のもと、D168の運用判定をstrict > 0.5へ切り替えました。運用開始は11月1日11:39（日本時間）。R6SとPi 5で同じ判定方針が使われ、既存の読取り処理が従来の17項目の照合条件を通り、画面用APIもdecision_threshold=0.5を返したことを、保存済み受入記録で確認しています。モデルを再学習した変更ではありません。

切替時はPi 5の通知・文脈確認・AI考察の既存3タイマーだけを約97秒休止し、元の周期へ戻しました。その後の通常周期は3処理とも正常終了し、NPUの識別情報を維持したまま採点数が増加しています。NPUと通常通信は止めず、旧通知の識別子、再通知を抑える待機状態、履歴、既存ジョブを保持しました。切替確認のための追加有料AI呼出しやテスト通知も行っていません。

3時間観察は別の比較方針で、入口・タイトル・集計条件はstrict > 0.5です。旧0.22のコードと集計状態を保全し、11月1日10:31（日本時間）を新しい観察専用累計の基点としました。これは11:39の運用開始とは別です。初回読取りは成功し、基点以降の確定6分区間は超過0、保持されたday窓は659分区間で超過0でした。後者は約11時間の保持範囲を0.5で見直した比較で、完全な24時間観察ではありません。欠測スコア数は未測定であり、超過0を検出性能や確定FPRの証拠にはしません。

今回確認したのは、0.5の適用と通常周期・読取り・APIでの整合です。切替後に新しい自然超過を起点として通知→文脈確認→Terra考察まで一巡したことを、新たに試験・確認した結果ではありません。同日後続のr62では説明文を含むPC／狭幅画面の受入も完了しました。これはその版の画面確認であり、後から変更したNPU構成に対する監査画面の受入へ自動的に広げません。過去の通知本文を新しい0.5へ書き換えてはいません。
